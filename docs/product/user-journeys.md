# Parcours utilisateur

## Statut

Validé en Phase 1 — Cadrage produit. Les wireframes et décisions UI détaillées relèvent de la Phase 2.

## Parcours principaux

### Parcours 1 : Découverte du profil

Un visiteur arrive sur la landing page, comprend le positionnement en moins d'une minute, identifie les technologies clés, consulte le résumé et accède aux sections principales.

Critères :

- le nom, le titre et la proposition de valeur sont visibles immédiatement ;
- les CTA principaux sont identifiables ;
- aucune statistique fictive n'est affichée.

### Parcours 2 : Évaluation technique

Le visiteur consulte les compétences, expériences et projets, ouvre une page de détail projet, vérifie le rôle, les technologies, les défis et les résultats disponibles, puis accède au CV ou aux liens professionnels.

Critères :

- les compétences sont catégorisées ;
- les projets mettent en avant problème, rôle, solution, technologies et résultats disponibles ;
- les projets confidentiels ne révèlent aucune information sensible.

### Parcours 3 : Demande de contact

Le visiteur ouvre la section Contact, renseigne le formulaire, accepte la politique de confidentialité, soumet la demande, reçoit un retour clair de succès ou d'erreur, et le message est enregistré côté administration.

Critères :

- erreurs de validation compréhensibles ;
- double soumission empêchée ;
- consentement requis ;
- spam pris en compte.

### Parcours 4 : Mise à jour de contenu par l'administrateur

L'administrateur se connecte, modifie un projet ou une compétence, prévisualise, publie ou garde en brouillon, puis vérifie que le site public affiche uniquement la version publiée.

Critères :

- brouillon non public ;
- publication explicite ;
- ordre d'affichage modifiable ;
- état de sauvegarde visible.

### Parcours 5 : Gestion des messages

L'administrateur consulte les messages, filtre les statuts, marque un message comme lu ou à répondre, classe un spam ou archive une demande traitée.

Critères :

- nouveau message en statut `NEW` ;
- statuts métier disponibles ;
- aucun message exposé publiquement.

### Parcours 6 : Gestion multilingue

L'administrateur prépare ou modifie les contenus français et anglais. Le système applique la stratégie documentée si une traduction est absente.

Critères :

- français par défaut ;
- anglais disponible dans le MVP ;
- absence de traduction traitée selon une règle validée en Phase 2.

## Parcours secondaires

### Parcours 7 : Gestion d'un média

L'administrateur téléverse une image ou un CV PDF, renseigne un texte alternatif lorsque pertinent, associe le média à un contenu, puis ne peut pas supprimer sans avertissement un média utilisé.

### Parcours 8 : Préparation SEO

L'administrateur modifie les métadonnées d'une page ou d'un projet. Le site public expose les informations compatibles avec l'architecture de rendu retenue.

## Ordre public recommandé MVP

Hero, crédibilité factuelle, À propos court, compétences structurées, projets mis en avant, expériences, services, méthode, contact.

## Points à clarifier en Phase 2

- Priorité exacte des sections sur mobile.
- Forme du niveau de compétence qualitatif.
- Stratégie de traduction absente.
- Parcours de récupération du mot de passe.
- Contenu minimal réel disponible pour la première mise en ligne.
